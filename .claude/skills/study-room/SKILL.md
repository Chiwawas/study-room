# 学习室：开课、写课、批改

学习室是一个本地网页（默认 http://127.0.0.1:4173），课存在仓库的 `data/study.db`，页面自己读，写进库刷新就能看到。
下文的命令都在学习室仓库根目录下运行（在仓库里启动 Claude Code 就会自动带上本 skill）。
所有操作走 `python3 tools/study_admin.py`（不带参数打印完整用法和 JSON 格式）。
样板课：`examples/rag/course.json`（大纲）、`examples/rag/1-1.json`（第一课），写之前先读 1-1.json。

## 1. 开新课：先摸底，再排大纲

用户在书房首页「我想学」写下的主题用 `study_admin.py wishes` 看；开了课用 `wishes id done` 标掉。

同一个主题，零基础和进阶的讲法完全不同，所以不摸底不写课。先问三件事：

- **起点**：现在懂到哪（零接触 / 知道大概没深究 / 懂原理想动手）
- **终点**：学完要能做什么
- **讲法**：类比多还是代码多、碰不碰数学、想多拿身边的例子还是多讲原理

摸底写进大纲 JSON 的 `profile: {start, goal, style}`，大纲每课带 summary、key_points、est_minutes。
**大纲先给用户看**，点头再 `course-import`。已导入的课要改摸底用 `course-profile`。
大纲 JSON 放 `courses/<课名>/course.json`，每课正文放同目录 `<单元>-<课>.json`，方便以后改了重新导入。

## 2. 写一课

写之前 `study_admin.py show 课程id` 看大纲和 profile，照 profile 定深浅；再读前一课，接上它结尾的「下一课」。

结构（不是死规定，但大多数课照这个走）：

1. **引子**：一个具体场景或反常现象，两三段，不下定义
2. **正文**：2–4 个 `## 小节`，每节先类比、再讲原理、再给真实例子
3. **对照表**（有可比较的东西时）放 note 框
4. **要点框**（key）：一句话记住这课
5. **当心框**（warn）：常见误解或这招的代价
6. **身边的例子**（可选）：拿用户日常会碰到的产品或场景对照，放 note 框
7. `## 下一课`：一两句引到下一课
8. `## 延伸阅读`：一两条原始资料

内容块：`text`（md）、`callout`（md + tone）、`code`（lang、code、caption）、`figure`（src、caption）。
一课 15–30 分钟能读完；超了就拆，跟用户说一声。

### 图文并茂

- 有两样以上东西可比（方案、参数、优缺点）就画表，md 表格放 text 或 note 框里；表不超过 4 列，手机上才放得下
- 讲流程、结构、数据怎么流动就配图，一课一两张，放在讲到它的那段后面；纯装饰的图不放
- 画法：写一个 HTML，图画在 `id="fig"` 的元素里（inline SVG 或 HTML 方框箭头都行），宽 680px、底色 `#FAF9F6`、字用 `Noto Sans CJK SC` 或系统中文字体、字号不小于 15px，
  然后 `python3 tools/fig.py 图.html 课id-序号.png` 渲染成 PNG；figure 的 src 写它打印的 `/fig/…`，caption 一句话说图在讲什么
- 图里的字要短，解释写在正文里；配色只用讲义已有的墨色、灰和要点蓝 `#007AFF`、当心橙 `#FF9500`

### 强调怎么用

每种标记只管一件事，不要为了好看乱加：

| 写法 | 显示 | 用在 |
|---|---|---|
| `**词**` | 加粗 + 淡玫瑰荧光底 | 要记住的术语，一节两三个 |
| `*词*` | 酒红 + 下划线 | 要当心的地方、反直觉的点 |
| `` `x` `` | 酒红小底 | 专有名称、文件名、函数名 |
| `[文字](网址)` | 虚线下划线 + ↗ | 原文链接 |
| 列表项开头 `**小标题**：` | 只加粗 | 列表里的分项名 |

callout 的 tone：`key` 要点、`warn` 当心、`note` 旁注、对照表、例子。框里的加粗不画荧光底。

### 资料与出处

- 讲到具体论文、数据、产品行为，要能指到原文；引用一律带原文链接，找不到出处就不写
- 链接只写自己确认过的地址，拿不准就去查
- 数字（版本、参数、阈值）查原始文档，不凭印象

## 3. 课后小测

每课 4–6 道，大致配比：单选 1–2、判断 1、多选 1、填空 1、简答 1。

- 考理解不考背诵：题干给场景，让用户判断该用什么、为什么
- 每题写 explanation，答错时看的就是这段，要说清为什么错
- 单选、判断的 answer 是选项原文；多选是选项原文数组；填空是可接受答案数组（同义说法都列上）
- 简答的 answer 写参考答案和给分要点，批改时照它看

写好一课：`study_admin.py lesson-set 课id 文件.json`。课 id 看 `show` 输出里的「课N」。
已经作答过的课，lesson-set 只更新讲义不动题目。

## 4. 自检，再交给用户

写完一课先截图自检，深浅色、电脑和手机宽度都看（服务要在跑，没跑就 `npm start` 放后台）：

```
python3 tools/shot.py /tmp/l.png --course 课程id --lesson 课id
python3 tools/shot.py /tmp/l-dark.png --course 课程id --lesson 课id --dark
python3 tools/shot.py /tmp/l-phone.png --course 课程id --lesson 课id --width 390
```

看图：表格、配图有没有挤出边、强调是不是用对了、框是不是太多。
然后告诉用户：这课讲了什么（三五行）、约多少分钟、几道题。用户说深了浅了就改，改法记进 profile 的 style。

## 5. 批改简答

- `study_admin.py pending`：列出待批改的简答
- `study_admin.py grade 作答id correct|partial|incorrect "评语"`：批改

评语先说对在哪，再说差什么，一两句话；差的部分指到讲义的哪一节。

## 6. 课上提问

用户问某课里的东西时，先 `study_admin.py show` 找到那课的 id，再 `study_admin.py lesson 课id` 读出讲义，按讲义当老师答：
答案对上讲义的说法和小节，讲义没讲到的就说是课外补充。
答得短，一次讲清一个点；用户要例子就举，问出讲义的漏洞就记下，写下一课或改这课时补上。
